# CK2 : journal des décisions — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal :** l'agent enregistre, avec l'accord de l'utilisateur, ses avis, les décisions prises, les scénarios comparés, les hypothèses et les revues, avec l'état du patrimoine figé au moment de la décision ; l'utilisateur relit, confirme, corrige et suit tout dans Agent › Journal ; rien ne se réécrit en silence.

**Spec :** `docs/superpowers/specs/2026-10-10-cockpit.md` § CK2 en détail. Dépôt `/Users/stephane/boussole`. Tests : `npm test`. Build : `node build.mjs`. Validation SQL locale : PGlite installé dans `/private/tmp/claude-501/-Users-stephane-Finance/6eb6e7ad-c778-4410-aa02-8f63b48b521c/scratchpad/pgl/` (voir `valider.mjs` pour les bouchons de l'environnement Supabase).

Ordre : 1, 2, 3, 4 en parallèle (fichiers disjoints) ; 5 (contrôleur) déploie.

### Task 1 : migration `supabase/migrations/0013_journal.sql` + `test/journal-db.test.mjs`
Table `journal`, déclencheurs (limite 2 000 avec `pg_advisory_xact_lock`, `maj_le`, historique hors `a_relire`), contraintes (types, statuts, longueurs, `options` tableau ≤ 6, `liens` objet, contenu sensible nommé `journal_contenu_sensible` sur titre/synthese/raisonnement), RLS propriétaire (`revoke all … from anon, authenticated` puis `grant select, insert, update, delete … to authenticated`), index `(user_id, cree_le desc)`, colonne `profiles.journal_consentement` (check des 3 valeurs, défaut `demander`), `export_all()` complété (repartir de la définition de `0009_savoir_memoire.sql` + `'journal'`). Tests statiques (modèle : `test/savoir-db.test.mjs`) + intégration avec clé de service (ignorée sinon) + script PGlite hors dépôt qui vérifie : insertion, refus IBAN, historique vide tant que `a_relire`, historique rempli après passage à `actif` puis modification, limite, export.

### Task 2 : connecteur — `supabase/functions/mcp/journal.ts` + intégration `index.ts` + `test/mcp.test.mjs`
Module `journal.ts` (modèle : `memoire.ts` / `savoir.ts`, dépendances injectées) : `registerJournal(server, h)` avec `journaliser`, `lire_journal`, `completer_journal`, `cloturer_session` ; `etatFige(donnees, ...)` reçoit en paramètre les fonctions de calcul d'`index.ts` (`bilan`, `bonnesPratiques`, `syntheseRisque`, lecture des repères) pour ne pas les dupliquer. `index.ts` : import, enregistrement, `demarrer_session` + `journal` et consentement, `CONDUITE_EXPERT` + règle de clôture, `INSTRUCTIONS` + journal, en-tête. Respect strict du consentement (lu dans `profiles.journal_consentement`, `demander` par défaut si null). `completer_journal` : note ajoutée en fin de `raisonnement` sous la forme « \n\n— Note du AAAA-MM-JJ (source) : … », jamais titre ni synthèse. Tests : outils enregistrés, 3 modes de consentement (exécution vm avec base factice, comme les tests de `memoire.ts`), `etat` présent, refus contenu sensible, `completer_journal` sans écriture de titre/synthèse, `cloturer_session` (consigne + écrits du jour), conduite et instructions.
